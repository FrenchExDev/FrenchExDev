# Injectable

Attribute-driven source generator for dependency injection registration. Declare service lifetimes on classes with `[Injectable]`, and the compiler generates container-specific wiring code at compile time. Zero runtime overhead, zero hand-written registration.

## Why

The developer who writes a service class knows its scoping requirements — thread safety, state management, resource disposal all differ between singletons, scoped, and transient services. Traditional DI wiring happens far from the implementation, forcing the bootstrapper to guess. Injectable moves that decision to the class itself.

```csharp
[Injectable(Scope = Scope.Singleton)]
public class CacheService : ICacheService { ... }

[Injectable(Scope = Scope.Scoped)]
public class RequestContext : IRequestContext { ... }

[Injectable]
public class EmailSender : IEmailSender { ... }
```

One line. The developer decides. The compiler wires.

## Quick Start

### 1. Add the attribute package

Reference `FrenchExDev.Net.Injectable.Attributes` in your service project.

### 2. Add a source generator

Choose the generator matching your DI container:

| Container | Generator Package |
|-----------|-------------------|
| Microsoft.Extensions.DependencyInjection | `FrenchExDev.Net.Injectable.Microsoft.SourceGenerator` |
| DryIoc | `FrenchExDev.Net.Injectable.DryIoc.SourceGenerator` |

### 3. Decorate your classes

```csharp
using FrenchExDev.Net.Injectable.Attributes;

[Injectable(Scope = Scope.Singleton)]
public class CacheService : ICacheService
{
    private readonly ConcurrentDictionary<string, object?> _store = new();
    public void Invalidate(string key) => _store.TryRemove(key, out _);
}

[Injectable(Scope = Scope.Scoped)]
public class RequestContext : IRequestContext
{
    public Guid RequestId { get; } = Guid.NewGuid();
}

[Injectable]
public class EmailSender : IEmailSender
{
    public Task SendAsync(string to, string subject, string body) =>
        Task.CompletedTask;
}
```

### 4. Call the generated extension method

**Microsoft DI:**

```csharp
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddMyAssemblyInjectables();
var provider = services.BuildServiceProvider();
```

**DryIoc:**

```csharp
using DryIoc;

var container = new Container();
container.AddMyAssemblyInjectables();
```

The method name derives from your assembly name: `MyApp.Services` becomes `AddMyAppServicesInjectables()`.

## Attribute Reference

### `[Injectable]`

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `Scope` | `Scope` | `Scope.Transient` | Service lifetime: `Transient`, `Scoped`, or `Singleton` |
| `As` | `Type?` | `null` | Explicit service type. If null, auto-detects from interfaces |

### Scope Mapping

| Scope | Microsoft DI | DryIoc |
|-------|-------------|--------|
| `Scope.Transient` (default) | `AddTransient` | `Reuse.Transient` |
| `Scope.Scoped` | `AddScoped` | `Reuse.ScopedOrSingleton` |
| `Scope.Singleton` | `AddSingleton` | `Reuse.Singleton` |

## Interface Resolution Rules

| Scenario | Registration |
|----------|-------------|
| `As` specified | Registers only as the specified type |
| No `As`, class implements interfaces | Registers for each directly implemented interface |
| No `As`, no interfaces | Registers as self (concrete type) |
| Abstract class | Skipped entirely |

```csharp
// Registers as IMyService only (IOther is ignored)
[Injectable(Scope = Scope.Singleton, As = typeof(IMyService))]
public class MyService : IMyService, IOther { }

// Registers as both IFirst and ISecond
[Injectable(Scope = Scope.Scoped)]
public class MultiService : IFirst, ISecond { }

// Registers as self (no interfaces)
[Injectable]
public class BackgroundJob { }
```

## Extension Method Naming

The generated method name is derived from the assembly name by stripping separators and applying PascalCase:

| Assembly Name | Generated Method |
|---|---|
| `MyApp.Services` | `AddMyAppServicesInjectables()` |
| `FrenchExDev.Net.Diem` | `AddFrenchExDevNetDiemInjectables()` |
| `Acme-Web-Api` | `AddAcmeWebApiInjectables()` |
| `some_lib_name` | `AddSomeLibNameInjectables()` |

## Generated Code Example

Given the source classes above, the Microsoft generator produces:

```csharp
// <auto-generated />
#nullable enable

namespace Microsoft.Extensions.DependencyInjection;

public static class MyAppServicesInjectableExtensions
{
    public static IServiceCollection AddMyAppServicesInjectables(
        this IServiceCollection services)
    {
        services.AddSingleton<global::MyApp.Services.ICacheService, global::MyApp.Services.CacheService>();
        services.AddScoped<global::MyApp.Services.IRequestContext, global::MyApp.Services.RequestContext>();
        services.AddTransient<global::MyApp.Services.IEmailSender, global::MyApp.Services.EmailSender>();
        return services;
    }
}
```

## Architecture

```
Attributes (netstandard2.0 + net10.0)
    InjectableAttribute, Scope enum

SourceGenerator.Lib (netstandard2.0, no Roslyn)
    InjectableEmitModel, InjectableServiceModel, InjectableEmitter

Microsoft.SourceGenerator (netstandard2.0, Roslyn)
    MicrosoftInjectableGenerator : IIncrementalGenerator

DryIoc.SourceGenerator (netstandard2.0, Roslyn)
    DryIocInjectableGenerator : IIncrementalGenerator
```

**Key design decisions:**

- **Container-agnostic attribute** — one `[Injectable]` attribute works with any DI container via separate source generator projects
- **Reusable emission** — `SourceGenerator.Lib` holds models and emitters without Roslyn dependencies, shared via linked files
- **Zero runtime overhead** — all registration code is generated at compile time; no reflection, no scanning
- **Single output file** — one `InjectableExtensions.g.cs` per assembly with a single extension method

### Source Generator Pipeline

1. `ForAttributeWithMetadataName` scans for `[Injectable]`-decorated classes
2. Each class is transformed into an `InjectableServiceModel` (implementation type, service types, scope)
3. All models are collected and combined with the assembly name into an `InjectableEmitModel`
4. The container-specific emitter produces the extension method
5. Output: `InjectableExtensions.g.cs`

## Adding a New DI Container

1. Create `FrenchExDev.Net.Injectable.{Container}.SourceGenerator` (netstandard2.0, Roslyn)
2. Add an `Emit{Container}()` method to `InjectableEmitter`
3. Implement `IIncrementalGenerator` following the existing pattern
4. Add a test project with fixture classes covering all scope and interface resolution scenarios
