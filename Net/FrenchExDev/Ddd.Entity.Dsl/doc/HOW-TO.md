## 1. Adding the Bridge SG

Reference the SG as an analyzer in your domain project:

```xml
<ItemGroup>
  <ProjectReference
    Include="path/to/FrenchExDev.Net.Ddd.Entity.Dsl.SourceGenerator.csproj"
    OutputItemType="Analyzer"
    ReferenceOutputAssembly="false" />
</ItemGroup>
```

Also reference the Ddd attributes and Entity.Dsl SG in the same project so both stages run.

---

## 2. Using DDD Attributes

Write your domain model with DDD attributes. Classes must be `partial`:

```csharp
using FrenchExDev.Net.Ddd.Attributes;

[AggregateRoot]
public partial class Order
{
    [EntityId]
    public Guid Id { get; set; }

    public string CustomerName { get; set; } = "";
    public decimal Total { get; set; }

    [Composition]
    public List<OrderLine> Lines { get; set; } = [];
}

[Entity]
public partial class OrderLine
{
    [EntityId]
    public Guid Id { get; set; }

    public string ProductName { get; set; } = "";
    public int Quantity { get; set; }
}
```

## 3. What Gets Generated

For each `[AggregateRoot]` or `[Entity]` class, the bridge SG emits a `.DddBridge.g.cs` file:

**`Order.DddBridge.g.cs`:**
```csharp
// <auto-generated/>
// Generated by Ddd.Entity.Dsl bridge — maps DDD attributes to Entity.Dsl attributes.
#nullable enable

namespace MyApp.Domain;

[global::FrenchExDev.Net.Entity.Dsl.Attributes.MappedEntity]
public partial class Order
{
}
```

**`OrderLine.DddBridge.g.cs`:**
```csharp
// <auto-generated/>
// Generated by Ddd.Entity.Dsl bridge — maps DDD attributes to Entity.Dsl attributes.
#nullable enable

namespace MyApp.Domain;

[global::FrenchExDev.Net.Entity.Dsl.Attributes.MappedEntity]
public partial class OrderLine
{
}
```

The Entity.Dsl SG then reads `[MappedEntity]` and generates the EF Core `DbContext`, entity configurations, etc.

## 4. Inspecting Generated Code

In Visual Studio / Rider, expand the project's **Analyzers** → **FrenchExDev.Net.Ddd.Entity.Dsl.SourceGenerator** node to see the generated `.g.cs` files.

Or check the output directory:


## 5. Planned Property Mappings

The `DddBridgeModel` already captures property-level DDD concepts, but the emitter doesn't yet emit them:

| DDD Property Attribute | Planned Entity.Dsl Mapping | Status |
|----------------------|---------------------------|--------|
| `[EntityId]` | `[PrimaryKey]` on property | Planned |
| `[Composition]` | Navigation with `OnDelete = Cascade` | Planned |
| `[Aggregation]` | Navigation with `OnDelete = Restrict` | Planned |
| `[Association]` | Navigation with `OnDelete = NoAction` | Planned |

When implemented, the bridge will emit property-level attributes in addition to the class-level `[MappedEntity]`.

---

## 6. Manual MappedEntity (Without Bridge)

If you don't use DDD attributes, you can add `[MappedEntity]` directly:

```csharp
using FrenchExDev.Net.Entity.Dsl.Attributes;

[MappedEntity]
public partial class Product
{
    public Guid Id { get; set; }
    public string Name { get; set; } = "";
}
```

The bridge SG is only needed when you want DDD attributes to automatically trigger Entity.Dsl generation.

## 7. Running Tests

```bash
dotnet test Ddd.Entity.Dsl/FrenchExDev.Net.Ddd.Entity.Dsl.slnx
```

Test suite: 3 xUnit tests verifying:
- `[MappedEntity]` attribute is emitted on partial class
- Auto-generated header and bridge comment are present
- Namespace is correctly applied
