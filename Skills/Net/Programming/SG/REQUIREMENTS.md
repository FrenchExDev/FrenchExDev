# SG (Source Generators) — Requirements

Non-negotiable rules for source generator development.

## Generator Type

- **Always use `IIncrementalGenerator`.** Never use legacy `ISourceGenerator`.
- **Always use `ForAttributeWithMetadataName`** for attribute-triggered generators. It is faster than `ForSyntaxProvider` because Roslyn caches attribute lookup.

## Project Decomposition

- **4-project decomposition is mandatory:** Runtime, .Attributes, .SourceGenerator, .SourceGenerator.Lib.
- **`.Attributes` must target `netstandard2.0;net10.0`.** Consumers on any TFM must be able to reference attributes.
- **`.SourceGenerator` must target `netstandard2.0`.** Roslyn analyzers require it.
- **`.SourceGenerator.Lib` must target `netstandard2.0` and must have ZERO Roslyn dependency.** No `Microsoft.CodeAnalysis.*` packages. This is the fundamental separation that enables reuse.

## Emission

- **Emission logic must live in `.Lib`.** The `.SourceGenerator` project only does Roslyn extraction (symbols, syntax nodes) into plain data models. All string building happens in `.Lib`.
- **Models must be plain data.** Strings, bools, lists, enums. No Roslyn `ISymbol`, `SyntaxNode`, or `SemanticModel` types may leak into `.Lib` models.
- **Reuse `BuilderEmitter` when generating builders.** Never write a second builder emitter. Use `BuilderEmitModel` extension points for customization:
  - `Preamble` — inject raw C# after class opening
  - `WithMethodAttributes` — add `[Attributes]` to `With*()` methods
  - `WithMethodBodyPrefix` — inject code before assignment in `With*()`
  - `InstantiationExpression` — custom expression in `CreateInstance()`

## Generated Code

- **Generated files must include `// <auto-generated/>` header** as the first line, so analyzers and coverage tools skip them.
- **Generated files must use `.g.cs` suffix** (e.g., `PersonBuilder.g.cs`).
- **Generated code must compile without warnings** in the consuming project.

## Roslyn Packages

- **Use `Microsoft.CodeAnalysis.CSharp 5.3.0` and `Microsoft.CodeAnalysis.Analyzers 5.3.0`.** These versions are pinned in `Directory.Packages.props`. Do not upgrade without checking all generators.

## Testing

- **Test generators using in-memory Roslyn compilations.** Create source text, compile with the generator, verify the output compiles and produces expected types/methods.
- **Test `.Lib` emitters independently.** Construct model objects manually, call `Emit()`, verify the output string.
